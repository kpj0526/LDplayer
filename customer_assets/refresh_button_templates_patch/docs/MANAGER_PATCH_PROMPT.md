# Manager 갱신 버튼 보완 지시

기존 패키지에 빠졌던 실제 임무 갱신 버튼 템플릿을 추가했다.

`assets/templates`의 다음 이미지를 기존 실행 템플릿 폴더와 template map에 병합하라.

- button_refresh_4400.png
- button_refresh_6600.png
- button_refresh_9900.png
- button_refresh_14900.png
- refresh_currency_icon.png

고객 영상에서 갱신 버튼은 갱신 횟수에 따라 4,400, 6,600, 9,900, 14,900으로 변한다. 하나의 고정 금액만 찾지 말고 네 템플릿을 OR 조건으로 탐색하라.

처리 방식:

1. 현재 상태가 `갱신 필요`인지 확인한다.
2. 현재 ADB 내부 화면에서 네 갱신 버튼 템플릿을 검색한다.
3. 가장 높은 유효 매칭 하나만 선택한다.
4. 발견된 전체 버튼 사각형의 중심좌표를 계산한다.
5. 같은 계정의 ADB 시리얼에 중심좌표를 탭한다.
6. `지역 퀘스트를 갱신하시겠습니까?` 팝업이 나타났는지 확인한다.
7. 팝업이 나타난 경우에만 기존 `button_refresh_confirm.png`를 찾아 클릭한다.

금액 OCR 결과만으로 버튼을 클릭하지 마라. 전체 버튼 템플릿을 우선 사용하고, 밝기 변화가 있는 경우 회색조·정규화·에지 기반 매칭을 보조로 적용하라.

`refresh_currency_icon.png`만 발견된 경우에는 아이콘 자체를 클릭하지 말고, 화면 레이아웃과 버튼 외곽을 함께 검증해 전체 갱신 버튼 영역을 확정한 경우에만 클릭하라.

팝업의 `확인` 버튼과 새 임무의 `수락 확인` 버튼은 글자가 같으므로 현재 상태 머신 단계와 팝업 제목을 함께 검증해야 한다.

목표 임무 판정은 기존 규칙을 유지한다.

- `모든 몬스터 처치 (0/200)` 전체 조건 확인 시에만 수락
- 조건이 맞지 않으면 다시 갱신
- 인식 실패는 재갱신이 아니라 재캡처 후 오류 처리

추가 후 production 코드에서 `button_refresh` 누락으로 중단되는 경로를 실제 템플릿 탐색과 ADB 클릭에 연결하라. 고정좌표 대체는 금지한다.

기존 Manager, code, qa만 사용하고 새로운 에이전트나 worktree를 만들지 마라. code가 구현한 뒤 qa는 네 금액 변형 모두에 대해 검색 위치 중심이 계산되고 다음 갱신 확인 팝업 상태로 전환되는지 검증하라.
