# Manager 최종 구현 프롬프트

이 ZIP은 고객 영상에서 직접 추출한 목표 임무 전용 이미지 패키지다. 저장소 최상단에 압축을 풀고 기존 프로젝트에 병합하라.

기존 Manager, code, qa만 사용한다. 새로운 에이전트, 하위 에이전트 또는 worktree를 생성하지 마라. 기존 작업을 폐기하거나 처음부터 다시 시작하지 마라.

## 목표 조건

실행 중 인정하는 목표 임무는 오직 다음 하나다.

- 문구: `모든 몬스터 처치`
- 목표 수량: `/200`

두 조건이 같은 새 임무 상세 화면에서 모두 확인될 때만 임무를 수락한다.

비목표 임무의 이름이나 이미지를 개별 등록하지 마라. 특정 몬스터 처치, `/250`, `/300` 등 목표 조건과 다른 모든 임무는 수락하지 않고 다시 갱신한다.

다음 세 결과를 반드시 구분한다.

1. `TARGET_CONFIRMED`: 목표 문구와 `/200` 모두 확인 → 수락
2. `NON_TARGET_CONFIRMED`: 정상적인 새 임무 상세 화면이지만 목표 조합이 없음 → 재갱신
3. `RECOGNITION_FAILED`: 새 임무 화면인지 또는 문구를 판정할 수 없음 → 재캡처 후 제한 횟수 초과 시 해당 계정만 ERROR

인식 실패를 비목표 임무로 간주하여 무한 갱신하지 마라.

## 이미지 기반 클릭

Windows 바탕화면에서 LD플레이어 창의 위치나 크기는 고정돼 있다고 가정하지 마라. 전역 화면 캡처와 마우스 클릭을 기본 방식으로 사용하지 않는다.

각 동작은 반드시 다음 순서로 실행한다.

1. 대상 LD의 ADB 시리얼로 내부 화면 캡처
2. 현재 상태에서 허용된 템플릿 검색
3. 매칭 점수 확인
4. 발견된 템플릿 사각형의 중심좌표 계산
5. 동일한 ADB 시리얼에 중심좌표 터치
6. 새 화면 캡처
7. 예상 화면 변화 확인 후 다음 상태 이동

`template_manifest.json`의 영상 추출좌표 또는 기준 해상도 좌표를 실행 중 고정 클릭좌표로 사용하지 마라.

## 필수 전체 기능

다음 순환을 TODO, placeholder, 로그 전용 함수 또는 production Mock 없이 실제 실행 코드로 연결한다.

`임무 화면 확인`
→ `자유 토벌작전 슬롯 선택`
→ `갱신 버튼 탐색 및 클릭`
→ `지역 퀘스트 갱신 확인창 탐색`
→ `확인 버튼 탐색 및 클릭`
→ `새 임무 상세 화면 확인`
→ `모든 몬스터 처치 + /200 동시 판정`
→ 조건 충족 시 `수락 확인 클릭`
→ 조건 불충족 시 `재갱신`
→ `다음 슬롯`
→ `5개 슬롯 목표 임무 확보`
→ `0~199/200 진행 중 대기`
→ `200/200 또는 완료 상태 판정`
→ `완료 버튼 클릭`
→ `보상 받기 클릭`
→ `보상 결과 닫기 클릭`
→ `임무 목록 복귀 확인`
→ `완료 슬롯 재갱신`
→ `전체 과정 반복`

이를 LD1~LD9 각각의 독립 Worker에 연결한다.

- LD1~LD9 자동 탐색 또는 최초 1회 매핑 저장
- 실행할 때마다 저장된 ADB 포트만 믿지 말고 현재 연결 유효성 확인
- 계정별 ADB 시리얼 분리
- 계정별 개별 시작·정지
- 전체 시작·정지
- 특정 계정 오류가 다른 계정에 영향을 주지 않음
- 전체 정지 후 예약 터치 제거
- 계정별 상태·현재 슬롯·최근 인식·최근 클릭·오류 로그 표시

## 진행과 완료 처리

- 0~199/200: 진행 중, 완료·보상 클릭 금지
- 200/200 또는 완료 표시: 완료 처리 시작
- 완료 클릭 후 보상 화면 출현 확인
- 보상 받기 클릭 후 결과 화면 출현 확인
- 닫기 클릭 후 임무 목록 복귀 확인
- 목록 복귀 후 해당 슬롯을 다시 목표 임무로 갱신

## 템플릿 관리

ZIP의 `assets/templates` 이미지를 초기값으로 사용한다. 고객 PC에서 다음 기능으로 교체·보정할 수 있게 한다.

- ADB 화면 캡처 저장
- 캡처 이미지 불러오기
- 템플릿 영역 선택 및 저장
- 템플릿별 매칭 임계값 설정
- 인식 시험과 매칭 위치 표시
- 현재 해상도에 대한 비율 또는 다중 크기 대응
- 누락되거나 인식되지 않는 템플릿 이름 표시

`progress_12_of_200.png`의 숫자 12를 고정 매칭하지 마라. 진행 숫자는 동적으로 판정하고 `/200` 분모와 완료 표시를 함께 사용한다.

## 구현 점검

code는 저장소에서 다음 항목을 검색하고 실제 경로로 연결하거나 제거한다.

- TODO
- NotImplemented
- placeholder
- 로그만 출력하는 클릭 함수
- 항상 성공을 반환하는 인식 함수
- production 코드에 연결된 Mock
- GUI에서 호출되지 않는 Worker
- 이미지 검색 없이 고정좌표만 누르는 버튼

Mock은 qa 자동 테스트 안에서만 허용한다.

## 현재 환경의 테스트 범위

현재 개발 PC에 LD플레이어와 게임을 새로 설치하지 않는다. 제공된 실제 영상 프레임과 가상 ADB 실행기를 이용해 다음을 검증한다.

- 목표 문구와 `/200` 동시 판정
- 목표 조건 충족 시 수락
- 정상 임무 상세 화면에서 목표 조건 불충족 시 재갱신
- 인식 실패 시 무한 갱신하지 않음
- 이미지 위치가 바뀌어도 발견 중심좌표 계산
- 임무 5개 순차 처리
- 진행 중과 완료 상태 구분
- 완료→보상 받기→닫기→재갱신 순서
- 9개 Worker 명령 격리
- 개별·전체 시작 및 정지
- 실제 ADB subprocess 실행 경로 존재
- Windows 실행파일 생성

실제 고객 PC에서 확인하지 않은 항목은 `NEEDS_REAL_TEST`로 기록한다. 그러나 실제 환경 미검증을 이유로 전체 production 실행 경로를 미완성으로 남기지 마라.
