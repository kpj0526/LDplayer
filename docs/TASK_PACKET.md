## 기존 MVP와의 차이

기존 MVP-001-CV는 5슬롯 갱신·완료·보상 순서를 코드와 fake recognizer로 모델링했다. 이번 요구사항은 이를 후속 범위가 아닌 MVP 필수 기능으로 승격한다. 특히 OpenCV/OCR 실제 구현, 실제 화면별 템플릿·ROI, 클릭 뒤 화면 변화 검증, 실 LDPlayer 전체 순환 1회 이상 검증이 새 필수 조건이다. 비용 숫자는 어떤 경우에도 고정 판별값이 아니다.

## code 전달 작업

1. `PlaceholderRecognizer`를 실제 PNG ROI 기반 OpenCV 템플릿 매칭 + 필요한 OCR recognizer로 대체하고, 낮은 신뢰도/미확인 시 절대 `MATCH`를 반환하지 않게 한다.
2. 고객 원본 캡처를 기반으로 모든 화면 요소의 템플릿, ROI, 탭 좌표, 임계값을 설정 파일과 템플릿 디렉터리에 분리한다. 추측값으로 PASS 처리하지 않는다.
3. 상태 머신에 명시 상태와 클릭 후 화면 변화 검증·정체 감지·계정별 `ERROR`를 보완한다.
4. 5개 슬롯 순차 확정, 이중 조건(문구+200), 가변 비용 팝업, 0~199/200 입력 금지, 보상·결과·복귀·재갱신 반복을 자동 테스트한다.
5. 실 ADB로 LD1부터 감독 실행해 검증하고, 통과한 변경만 커밋·인수인계한다.

## qa 전달 작업

신규 AC-61~90을 독립 검증한다. 목표/비목표 판별, 진행/완료 구분, 확인·완료·보상·닫기 오인식 방지, 가변 갱신 비용, 5슬롯 순차, 보상 후 재갱신, 계정 간 ADB 탭 격리, 실제 고객 화면 전체 순환을 시험한다. Fake 테스트 통과만으로 실제 환경 AC를 PASS 처리하지 않는다.

## 완료 게이트

새 요구사항의 실제 인식·입력·실 고객 LDPlayer 전체 순환이 확인되기 전에는 MVP 완료 또는 최종 PASS를 선언하지 않는다.
