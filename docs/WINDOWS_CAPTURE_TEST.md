# v1.0.3-rc.38 — Windows 캡처 / 커밋 메모리 시험판

rc.38은 보상 수령 후 새로 나온 `모든 몬스터 처치` 임무를 수치 이미지 불일치 때문에 갱신하던 문제를 수정한 고객 테스트용 버전입니다. 실제 LDPlayer 확인은 아직 필요합니다.

rc.37은 보상 수령 후 아직 진행 중인 다른 목표 미션을 다시 갱신하던 상태 초기화 문제를 수정한 고객 테스트용 버전입니다. 새 폴더에 압축을 풀고 아래 순서로 확인하세요.

rc.36은 이미 `완료` 상태인 목표 미션을 갱신 대상으로 오인하던 문제를 수정한 고객 테스트용 버전입니다. 새 폴더에 압축을 풀고 아래 순서로 확인하세요.

rc.35는 rc.34의 화면 영역 경계 오류를 수정한 고객 테스트용 버전입니다. 새 폴더에 압축을 풀어 아래 순서로 다시 확인하세요.

기존 rc.33과 별도로 새 폴더에 압축을 풀어 실행하세요. rc.33을 덮어쓰지 않습니다.
이 버전은 커밋 누수 해결을 확정한 버전이 아니라 원인을 비교 측정하기 위한 시험판입니다.

## 고객 PC 실행 순서

1. 기존 ldmanager를 종료하고 LDPlayer 한 개를 켭니다. 게임 해상도는 1280×720입니다.
2. ldmanager.exe 실행 → Refresh ADB devices → 해당 LD 패널에 serial 선택/Save.
3. Refresh LD windows → 해당 패널에서 정확한 LD 창을 선택합니다. 이름이 LD1일 필요는 없습니다.
4. 게임의 미션/지역 목록 화면에서 Test capture를 누릅니다.
5. 비교 창에서 ADB 이미지와 Windows 이미지가 같은 LD 계정인지 직접 확인하고
   Same LD - enable Windows capture를 누릅니다. 계정이 다르거나 모르겠으면 Cancel입니다.
6. Windows capture verified가 표시되면 그 LD만 Start합니다.
7. 기능 확인 후, 기존 문제가 재현됐던 같은 인스턴스 수·게임 조건으로 비교합니다.

두 이미지가 비슷하다는 사실만으로 계정이 같다는 것을 보장할 수 없습니다.
창의 PID/HWND에 연결하므로 창 제목이 비슷한 다른 LD를 자동 선택하지 않습니다.
창 크기를 변경하거나 최소화/종료하면 자동화가 중단될 수 있습니다. 복구 후 Test capture를 다시 합니다.
창 캡처 API 또는 GPU가 호환되지 않으면 Start가 막히며 ADB로 자동 전환하지 않습니다.

## 자동 기록

앱 실행 시부터 30초마다 `diagnostics/memory/<실행별 폴더>/`에 저장합니다.
Start 전에도 기록하므로 게임만 실행한 상태의 기준선을 얻을 수 있습니다.

- summary.csv: Windows 전체 커밋 사용량/한도, 커널 풀, 프로세스 그룹 메모리,
  누적 ADB 호출/프로세스 시작 시도 수, 캡처/탭 횟수 및 샘플 간 증가량.
- processes.csv: PID·프로세스 생성 시각·이름·그룹·Private Bytes·Working Set·측정 오류.
  LDPlayer/dnplayer/LDVBox/LD9Box 계열, adb, 현재 앱 및 다른 Python/ldmanager를 기록합니다.
- accounts.csv: serial별 연결된 HWND, 검증 상태, 누적 Windows 캡처 수와 마지막 오류.

모든 메모리 열은 bytes입니다. Private Bytes와 Working Set은 서로 다른 지표입니다.
프로세스 합계가 시스템 전체 커밋과 정확히 일치할 필요는 없습니다.
권한 부족/측정 실패는 빈 값과 error 열에 남기며 0으로 가장하지 않습니다.
각 CSV는 10MiB 단위로 다음 파일에 이어 쓰며, 앱 메모리에는 기록 전체를 쌓지 않습니다.

`adb_preflight_captures`는 Test capture에서만 발생한 ADB 스크린샷입니다.
`adb_runtime_captures`는 정상 운용 중 **0을 유지해야 합니다**.
`adb_calls`는 장치 조회+캡처+입력 명령의 호출 시도 수입니다.
`adb_process_starts`는 이 앱이 시작을 시도한 ADB 클라이언트 프로세스 수이며,
ADB가 내부에서 띄우는 서버 프로세스까지 세는 값은 아닙니다.
지속 shell은 여러 탭 명령에 재사용되므로 명령 수와 프로세스 수는 다릅니다.
`commit_delta_per_1000_adb_captures`는 해당 샘플 구간의 관찰 비율일 뿐 인과관계가 아닙니다.
ADB 캡처가 0건인 구간은 나눗셈을 하지 않고 빈 값으로 남깁니다.

## 비교 방법

게임 상태·인스턴스 수·게임/LDPlayer 설정을 맞추고 다음을 별도로 관찰합니다.

1. 게임만 실행하고 자동화는 멈춘 상태의 증가 속도.
2. 기존 rc.33 ADB 캡처 운용에서 확보한 측정값. WGC가 활성화된 rc.33은 ADB 기준선이 아닙니다.
3. 이번 시험판에서 운용 중 ADB 캡처 0을 확인한 상태의 증가 속도.

기존 버전에는 이 자동 로그가 없으므로 기존 측정 또는 Windows 성능 모니터가 필요합니다.
비교를 위해 위험한 ADB 고빈도 캡처를 이 시험판에서 켜는 스위치는 넣지 않았습니다.
시작 직후의 일시적인 증가와 지속적인 증가를 구분하고, 한도에 닿기 전에 시험을 멈춥니다.
자동화 중단은 LDPlayer 자체 메모리를 회수한다는 뜻이 아닙니다.
한 개가 정상이어도 여러 인스턴스 안정성이 입증되는 것은 아닙니다.

실패하면 해당 실행의 memory 폴더와 `diagnostics/captures/<LD>/`를 지원 담당자에게 전달합니다.
캡처에는 게임 계정 화면이 들어 있으므로 공개 게시하지 마세요.
ADB/원본 Windows/정규화된 게임 이미지가 저장되며, 비교 실패 시에도 확보한 원본은 남습니다.

실제 LDPlayer/GPU에서의 캡처 호환성과 커밋 개선 효과는 고객 PC에서 검증해야 합니다.
